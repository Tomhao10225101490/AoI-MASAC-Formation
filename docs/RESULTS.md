## 结论

领队每一步都广播。另一条邻机信道上，每一步只让**当前领队信息最新的那一架僚机**再发一次。这一次转发不占用领队的时隙。

领队自己在加减速时，这一次信标拿回了“四架每步都转发”的大部分收益。领队匀速时，跟踪器本来就跟得上，信标只少大约 1 米。

主实验没有侧风，碰撞率是 0。误差是通信造成的，不是擦楼造成的。

## 为什么不把领队的时隙让出去

同一批随机种子上比过三种时隙账单。四架每步都转发、但不占领队时隙，最难一格从 49.9 米降到 27.6 米，最差 10% 从 106 米降到 58 米（`results/relay_free`，当时还有侧风，绝对数和主实验不同，方向一致）。

每 2 个时隙拿 1 个给最新的僚机、领队少说一次（`results/relay_tdma`），同一格只到 46.6 米，最差 10% 反而到 125 米。每 4 个时隙拿 1 个（`results/relay_tdma4`）同样没有把收益找回来。按信息年龄决定这个时隙还给领队还是拿去转发（`results/relay_yield`，门限 1、2、4、8 步）也没有一个门限在所有格子上同时赢。

所以收益来自**多一次不占用下行的转发**，不是来自把领队的发言时间分给僚机。

## 方法

### 场景

`scenario: canyon`，代码在 `envs/scenario.py` 和 `envs/formation_env.py`。

地图 1200 m × 800 m，高度 15–120 m。领队沿 y = 400 m 从 x = 120 m 飞到航路点 (600, 400, 40) 和 (1120, 400, 40)。四架僚机在领队后方，横向分别在 ±1 条街和 ±2 条街。街道之间是四排矮楼，高度都低于升限，所以链路可以被楼切断，也可以从上面看过去。计分到领队 x ≥ 1040 m 为止，避免领队停在终点后航向乱转、槽位跟着转。

主实验每回合重抽街区（`canyon_random`）：街宽 66–84 m，楼半径 12–14 m，沿街间距 48–56 m，高度 48–78 m，位置抖动 ±2 m，路口每隔 4–6 栋空一格。生成时保证每条车道中心到楼边缘至少 8 m。固定街区（街宽 70 m，半径 14 m）只用于早期探针，不是主表。

### 飞机

步长 0.2 s，最多 750 步。领队由航路跟踪器开，不学习。僚机由槽位跟踪器开：前馈领队地速，沿航迹补上落后的距离，并对风做侧滑补偿。主实验把风关掉（`randomize_wind: false`，`wind_speed: 0`）。打开 0–4 m/s 侧风时，飞机会被吹进楼排，完美信息也会有大约两成回合擦楼，误差就不再只是通信。

机动（`leader_jink: 1`）是加在领队速度指令上的分段常数扰动，每 10 步重抽一次，幅度对应巡航速度 ±6 m/s，不加偏航。`leader_jink: 0` 是匀速。卡尔曼滤波器按常速度外推，所以机动会在丢包期间把槽位拉偏。

### 链路

距离模式：成功概率 `p0 · exp(−d / d0)`，`d0 = 200` m。线段切到楼体（不是地面脚印）时再乘穿透系数 `nlos_factor`。主实验扫 `nlos_factor ∈ {0.2, 0.01}` 和 `p0 ∈ {0.6, 0.3}`。切到楼但穿透系数小，表示楼几乎不透。

僚机只从这条下行得知领队，机载“最近队友”不包括领队。收到包就重置卡尔曼信念，信息年龄归零。丢包就按常速度预测一步，年龄加一，年龄封顶 40 步。

### 四种转发

实现在 `UAVFormationEnv._update_channel`，开关是 `relay_mode`。

- `off`：只有领队，每步对每架僚机独立试一次。
- `beacon`：领队仍然每步都发。另外每 `relay_period` 步，**恰好一架**僚机在邻机信道上广播自己手里的领队信念。接收者只在这份信念比自己的更新鲜时采纳，年龄比发送者大 1 步（一跳）。邻机信道用同一套距离和穿楼模型。`beacon_select` 为 `freshest`（信息年龄最小，平局取编号小的）、`random` 或 `round`。
- `free`：领队每步都发，并且四架僚机每步都转发。这是上界：四次额外发射，彼此不碰撞。
- `tdma`：每 `relay_period` 步有一步领队不发，那一步只由最新的僚机转发。`relay_aoi_gate ≥ 0` 时，如果全队最新的年龄还小于这个门限，这一步还给领队。

主实验的触发器名字直接决定模式，不看 `args.json` 里的 `relay_mode` 默认值：`none`、`b5`、`b2`、`b1`、`b1:random`、`free`。

没有训练网络。跟踪器是脚本。这样差出来的米数是转发规则的，不是求解器的。

### 指标和对照

每个回合先对所有僚机、所有计分步平均，再对回合平均。

- `e3`：三维槽位误差。
- `eh`、`ez`：水平和垂直分量。主实验里垂直分量接近 0，因为没有人在爬。
- `e3_episodes`：逐回合的 `e3`，用于配对。
- 最差 10%：回合均值的 CVaR90。
- `collision`：该回合是否发生过机体与楼或机体之间的重叠。主实验这一列是 0。

配对差是同一 `seed`（从 7000 起，每个回合加 1）上两种触发器的 `e3` 相减。标准误是这 80 个差的样本标准差除以 √80。没有做显著性检验的星号，表里的 ± 就是这个标准误。

重跑主实验：

```bash
python scripts/voi_probe.py \
  --out results/relay_beacon --episodes 80 --workers 9 \
  --jinks 0,1 --nlos-factors 0.2,0.01 --p0-values 0.6,0.3 \
  --no-blockage-control --canyon-random \
  --triggers none,free,b1,b2,b5,b1:random
python scripts/plot_beacon.py results/relay_beacon/voi.csv
```

## 检验过、没有成立的说法

这些负结果留在本地的 `results/day`、`results/voi_canyon`、`results/relay_tail`，没有放进这个提交。它们解释了为什么正文不是原来那个题目。

1. **学出来的残差几乎是 0。** 一天的 MASAC 训练之后，信念观测和去掉槽位标准差的观测，编队误差相同。回放检查点，策略动作幅度约 0.0002。策略没有在用这个通道。
2. **爬高换测量，按三维误差不划算。** 跟踪器修好之后，完美信息的误差只有几米到十几米。脚本规则在不确定时爬到刚好看见领队的高度，多付的垂直误差通常大于少掉的水平误差。只有“领队机动强、楼几乎不透”的角上，爬升能把尾部拉下来，而且不稳定。
3. **一架爬高给全队当中继，同样要看时隙账单。** 转发免费时，爬高相对“只转发、不爬”没有稳定的额外收益。转发要占用领队时隙时，连转发本身都不稳。
4. **侧风会把结论弄脏。** 0–4 m/s 的侧风让完美信息的跟踪器也擦楼。主实验关掉风之后，碰撞率为 0，领队机动仍在。

`configs/canyon_relay_masac.yaml` 是按“学习谁来爬”写的训练配置。主表不使用它。在上面这些负结果之后，没有再跑长时间训练。
