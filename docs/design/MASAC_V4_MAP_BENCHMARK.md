# V4 三维地图与联合可行性基准设计

2026-11-03。此文件先定义可实现接口和验证门槛；在 V3 失败审计及项目阶段切换完成前，不将其当作已验证的训练基准。核心任务仍是三机独立目标的 MASAC 三维路径规划。地图、参考规划与轨迹检查是实验基础设施，不作为候选创新。

## 目标与边界

保留 `240×240×90 m` 作为默认世界及现有比较尺度；可配置的更大世界只用于独立的泛化场景，不能与默认世界的训练和评估混算。默认 `dt=0.2 s`、`vmax=10 m/s`、`amax=4 m/s²`、350 步上限；全队需在同一时刻各自距目标小于 4 m 且速度小于 2 m/s。参考执行不得通过冻结位置或瞬间改变速度制造到达。V4 诊断若需要不同的时间期限或奖励定义，须先在独立协议记录，不能在地图更换时悄悄改变。

## 场景表示与接口

新建独立的 V4 场景模块和环境模块，不覆盖已有 `structured.py` 或 `shared_masac.py`。场景生成接受显式配置、布局名、难度和地图种子；以纯数据结构返回世界边界、静态障碍 AABB、道路/通道语义、各机起终点、移动障碍初始状态与已声明运动规则。高架桥的桥面使用悬空 AABB，桥墩分别建模；U 形庭院由多个 AABB 组成，避免用实心包围盒填平庭院。场景附完整配置、种子和依据规范化 JSON 字节计算的 SHA-256；存储精确数值并拒绝 NaN。

环境接口为 `V4Mission(scene).reset()` 和 `step(actions)`，返回观测、团队平均奖励、碰撞/成功终止、时限截断与信息字典。场景对象只由环境和离线审计持有。训练 Actor 的输入可先提供与 V3 Pooling 兼容的 162 维适配：自身任务/状态 20 维、最多 5 邻机、最多 8 静态对象、最多 4 动态对象及 19 维预留通道；不足数量使用零填充和有效 mask。动态对象数量可配置为 0 或更多，超过接口槽位时只暴露规则确定的最近可见对象；该截断、感知半径及排序必须记入配置，不得将未显示对象描述为不可碰撞。注意力结构使用另行冻结的对象类型接口，不能从环境真值旁路到 Actor。

Actor 允许自身位置、速度、前次执行加速度、自身目标及动力学参数；邻机和障碍仅允许感知半径内的当前相对位置、速度和尺寸。无参考路径、未观测地图、其他机目标、当前以后的移动障碍真值或审计器状态。感知半径之外的对象无有效 mask；允许全局自身目标不等于允许全局地图。Critic 使用 CTDE 允许的信息，其精确信息集由网络协议单独规定。

V3 实际上没有感知半径裁剪：它输入全部邻机、全部 4 个动态障碍及最近 8 个建筑。V4 的局部半径是明确的信息集变化，不能将相关效果全部归因于地图或网络。首个 L0 基线使用覆盖整个世界的半径（至少世界对角线），并限制静态对象不超过 8 个、动态对象为 0，因而所有 L0 相关对象和邻机均可观测；不足槽位必须用零与 mask 填充。此时保留相同的 162 维容量，后续缩小感知范围和扩大对象槽位分别是独立的表示/可观测性对照。V4 Attention 允许从已有对象槽位和 mask 生成类别 token，不能仅在某一组增加可见对象。

默认局部模型是理想的距离受限感知，静态对象以到 AABB 表面的距离、球形对象以表面净距以及邻机中心距离筛选；距离内对象不因建筑遮挡被隐去，因此不应称作真实遮挡传感模型。对象超出槽位时按距离和稳定 ID 排序。另设视线遮挡模型须重新冻结并独立验证，不能暗中改变此接口。

参数覆盖世界尺寸、建筑密度和高度范围、道路/走廊宽度、拐角/遮挡布局、起终点距离/方向/高度差、动态障碍数量/速度/运动模式、机体半径与安全裕量、三机路径交叉程度。输入超出已实现范围或与难度约束冲突时明确拒绝或记录为非标准配置，不能静默降级。训练、开发和最终测试地图种子空间分开，并在实验协议中提前冻结；未用于选择的确认集不能事后混入开发集。

## 六类几何与 L0–L3

1. **urban_canyon**：混合高度街谷、道路与交叉口；高度分布和道路宽度可控。
2. **warehouse**：大体积仓储遮挡和作业通道；不只通过数量改变难度。
3. **courtyard**：带开口的 U 形组合、庭院和死胡同；开口朝向及转角可控。
4. **overpass**：带墩柱的悬空桥面，保留上方和下方不同高度通道。
5. **narrow_crossing**：狭窄通道与多机交汇，交汇角度、间距和路径冲突等级可控。
6. **dynamic_crossing**：在静态结构背景下布置移动障碍的穿越；数量、初始相位、速度、方向和受限反弹/静止等模型显式记录。

L0 是三机简单静态导航：宽通道、较短目标、零动态障碍和低冲突；可保留不遮挡任务走廊的静态背景。L1 是常规静态建筑绕行，增加遮挡和距离。L2 是复杂静态三维通道、高度差、转角与死胡同。L3 包含移动障碍、多机交汇及更强路径冲突。难度由具体几何、航程、速度和交会条件共同控制；每张场景记录生成参数及实际最小通道和任务距离，不以建筑数单独定义难度。

默认开发预设将 L0–L3 的起终点欧氏距离设为 40/150/150/150 m、高度差设为 0/0/16/8 m、通道宽度参数设为 24/18/12/10 m，L0–L2 动态障碍为 0、L3 默认为 4。各机 L0 起点在固定空旷走廊内按场景种子小幅扰动，目标相对位置保持 40 m；这让训练和开发种子对应不同起终点，而非只随机背景。L3 的 dynamic_crossing 至少一个障碍在标称中线附近、与航路高度相交；实际时间冲突取决于控制动作和场景，是否碰撞由逐步执行记录。以上仅是预设，且并不保证难度单调或代表真实城市。

布局族与难度相互独立配置，但若请求的组合无法满足定义或联合参考验证，显式记为生成/验证失败；不得悄悄移除障碍、改目标或声称全部组合可行。L0 只能含静态任务；需要动态对象的 `dynamic_crossing` 在 L0 的静态变体须标记为零动态，不能被描述为动态避让实验。3–6 机接口可扩展，首个联合可行性门槛和训练阶段固定为 3 机。

## 可行性审计：两道不同门槛

1. **静态几何连通。** 按机体半径与配置安全裕量膨胀静态 AABB，构建注明分辨率的三维占据网格；检查所有机起终点及网格连通路径，并对路径连接线段执行与环境相同的连续线段/AABB 交叉检查。网格无法找到路径时记为“未找到”，不是对连续空间不可行的证明。静态连通不包含动力学、移动障碍、机间冲突或时限。
2. **三机联合参考执行。** 离线参考规划器可以读取完整静态场景并生成路标，使用实际环境动力学以有限加速度跟踪；三机同时逐步执行，移动障碍按已声明规则运动，途中使用同环境的扫掠静态/机间/动态及边界碰撞检测。允许安全等待和速度受限的到达保持，但不允许隐式瞬移、冻结或替换执行动作。仅当实际环境在 350 步内返回全队同时满足到达条件、且没有碰撞/越界，才记录 `joint_reference_success=true`。记录每机真实状态与动作、最小净空/机间间距、速度和加速度上限、实际用时、终止原因以及参考控制器配置。该见证只证明具体场景/轨迹在模拟器规则下可执行，不证明策略安全或所有任务可行；失败也不证明不存在其他可行策略。

参考控制器可采用保守膨胀网格路径、线段简化、速度限制和逐机路标跟踪；交叉场景可使用预先记录的出发延迟或高度分离。所有候选延迟、路标和失败须由审计器记录，不能隐藏反复试错。参考规划器只用于离线审计与可视化，不提供训练示范、额外奖励或 Actor 输入。

## 输出与测试

每次生成记录配置、布局、难度、地图种子、几何/场景哈希、障碍数量、高度范围、起终点距离、障碍初始状态和明确的失败原因；不只保存成功地图。对固定开发样本生成六族场景清单、连通与联合参考执行原始数据、可重放动作/轨迹文件及独立的可旋转三维 HTML。HTML 显示真实建筑、桥面、起终点和实际保存的参考轨迹；动态回放仅使用真实记录，不生成虚构成功路径。它是开发展示，不代替地图和轨迹数据。

必要测试包括固定种子和哈希重现、非重叠/最小通道净空、悬空障碍与 U 形开口、世界边界、变长对象与 mask、Actor 对不可见/未来信息的隔离、动力学/线段碰撞一致性、参考动作受限、三机联合冲突及 70 秒终止。每个报告场景必须按门槛分别给出几何和联合执行状态；失败数量和生成种子一并保留。训练或泛化结论还需要独立地图与训练种子，地图渲染和参考控制器本身不能证明学习结果。
