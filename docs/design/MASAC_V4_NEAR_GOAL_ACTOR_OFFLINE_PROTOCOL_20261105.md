# Frozen offline near-goal actor-response audit (2026-11-05)

This protocol specifies a descriptive audit after the registered 40k experiment. It does not change that experiment, its final endpoint, its advancement rule, or either absolute gate. Observed final trajectories include never-ball agents whose closest distances are 4–10 m and whose final speeds are below 2 m/s. Those observations do not identify a cause. This audit asks how each history's final actor responds to its own late-training replay observations, including the predetermined near-goal subset.

Reuse exactly the six histories and observations in `results/masac_v4_sync_40k_late_content_audit_20261105/audit.json`: static control and static+B, seeds 1511, 1522, and 1533. Each replay contains 40,000 transitions; select 1,024 joint observations from its last 8,000 transitions using integer ranks `floor(k*7999/1023)`, `k=0,...,1023`, and physical indices `32000+rank`. The existing `sample_indices.json` SHA-256 is `eca0cfd9c12108af9627b89910fcf6a657c168a9c1bb54622eb628d15d3b3fc7`. All indices, replay hashes, and sampled observation canonical hashes must match Phase A. There are 6,144 joint observations and 18,432 agent observations, which are correlated replay observations, not independent replicates.

This is the late-training replay population of static/control and static+B policies. It is neither final-policy on-policy sampling nor a historical full-probe policy population. Do not select failures, add observations, query sealed maps, or roll out an environment. Pooling is descriptive; report every history and arm, including empty subsets. The fixed primary subset is `4 <= d < 10` m and `speed < 2` m/s. Also report all observations and the complete distance-bin by speed-bin table: `[0,4)`, `[4,5)`, `[5,10)`, `[10,infinity)` crossed with `<2` and `>=2` m/s. ## Trusted actor extraction and fixed noise

For each history use only its own final-40,000 checkpoint. Before deserialization, verify the actual checkpoint bytes against its previously verified manifest and Phase A checkpoint SHA; verify replay, manifest, configuration, and frozen source hashes as well. The self-generated checkpoint is a trusted local pickle container: `torch.load(..., map_location='cpu', weights_only=False)` may decode packaged critic/optimizer/environment objects, but this audit consumes only `payload['model']['actor']`. Instantiate only `Actor('pool')`; strictly load its actor state; do not instantiate a learner, critic, target, optimizer, or environment. No update, saved-RNG restoration, action rollout, or gradient is allowed. Constructor random draws are isolated with `torch.random.fork_rng`; record and verify actor-state hashes before and after inference and unchanged process torch RNG states. Checkpoints are not evidence of exact CUDA resume.

Compute the frozen static provider features on the same raw observations. Extract actor parameters through the exact frozen feature/body/head operations:

`h = actor.body(actor.features(obs, risk=static_risk))`, `mu = actor.mu(h)`, `log_std = actor.logstd(h).clamp(-5, 1)`, `std = exp(log_std)`.

The deterministic response is `a_det = tanh(mu)`. This is not the expectation of the squashed Gaussian action. Generate exactly 64 standard-normal vectors of dimension 3 in float32 using a separate CPU `torch.Generator` with seed 20261105. Save the vectors and their canonical bytes hash. Reuse those same vectors for every observation, agent, and history:

`a_k = tanh(mu + std * eps[k])`, `k=0,...,63`.

The common vectors provide paired **per-agent marginal** Monte Carlo summaries. They do not sample independent agents from the team product policy. Never report a team joint capture probability from these draws. There are no confidence intervals, significance tests, or independent-sample claims. Run one actor feature/body pass per chunk of 128 joint observations, then vectorize the 64 action draws. Use one torch thread and CUDA when available as requested; do not call the network 64 times.

## Observation decoding and one mathematical kinematic step

Decode the stored float32 observation into float64 arithmetic. For the frozen observation format, goal displacement is `delta = obs[0:3] * max(world)`, position is `obs[9:12] * world`, `vmax = 20*obs[18]`, `amax = 10*obs[19]`, and velocity is `v = obs[3:6] * vmax`. Obtain `world` and `dt` from the verified configuration/provider defaults. This cannot recover original simulator precision. Count starting and resulting distances/speeds within `1e-4` of the strict 4 m / 2 m/s boundaries; do not exclude them or relax predicates.

Use a last-axis vectorization equivalent to the frozen `structured.limited` helper on clipped normalized actions, without creating an environment. Before actor inference, cross-check four fixed vector cases (including acceleration-norm limiting and speed clipping) against the original helper. Its operations are:

`u = clip(a, -1, 1) / max(1, norm(clip(a,-1,1)))`,

`w = v + dt*amax*u`, `v_next = w*min(1, vmax/(norm(w)+1e-12))`,

`delta_next = delta - dt*v_next`, `a_executed = (v_next-v)/dt`.

This matches the environment's component action clip, norm acceleration limiter, speed limiter, and semi-implicit position update. It is a **one-step kinematic counterfactual**, not a feasibility, collision, peer-motion, episode-success, or return prediction. In particular, a bounded-speed terminal capture step necessarily has `d < 4 + dt*2 = 4.4` m by the triangle inequality. Report the additional state-dependent necessary condition `d < 4 + dt*min(2,vmax,norm(v)+amax*dt)` for states starting at `d>=4`; it is not sufficient for capture. At rest with nominal `amax=4`, the latter bound is 4.16 m. Preserve the primary subset and all observations regardless of these bounds. Zero single-step capture for states 5–10 m away therefore cannot diagnose ineffective control. An outward/braking response may be appropriate for constraints omitted by this counterfactual; no optimality or causal conclusion follows.

For nonzero goal displacement define inward unit vector `e = delta/norm(delta)`; set this vector to zero at exact distance zero and report that count. Report executed inward radial acceleration `dot(a_executed,e)`, tangential acceleration norm, acceleration norm and radial cosine, one-step distance change `norm(delta_next)-norm(delta)`, and resulting speed/distance. Also report requested acceleration `amax*u` separately from executed acceleration after the speed limiter. Zero-distance radial terms use the declared zero-vector convention, which does not establish a physical radial direction; radial cosine is set to zero when either displacement or executed acceleration is zero, with the undefined-direction count reported separately. No observations are dropped. Do not silently drop nonfinite values. Strict single-agent capture is exactly `norm(delta_next)<4 and norm(v_next)<2`. Report deterministic counts, stochastic marginal counts out of `64*n`, and per-state marginal capture fractions. Starting in the strict set measures retention, so retain separate counts for retention and acquisition from outside the starting strict set. Zero captures in 64 draws do not prove zero true probability. Never label these counts environment success.
