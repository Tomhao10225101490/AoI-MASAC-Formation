# Structured V3：两条标准基线训练历史的等预算续训

2026-11-03。用户要求本批结束后继续分析、优化并提高训练轮次。本协议先冻结下一项开发诊断；研究方向仍为 MASAC 多无人机三维路径规划，不排队训练候选机制臂。下面的 `curriculum` 和 `original` 都是同一个 Standard MASAC 算法，表示两条已有训练历史，不是不同网络或不同安全机制。

课程批次三种子均完成 100,000 环境步、99,000 次更新，最终原六张开发图均为 0/6；对应原无课程 100,000 步基线也均为 0/6。课程组在种子 411/422/433 的平均剩余目标距离分别为 141.96/117.29/121.99 米，对应原组为 121.97/126.90/136.73 米，表现有升有降。课程组已结束短程任务 1,306 回合、完整任务 3,643 回合，均无全队成功。证据分别是课程批次 `completion.json`、`final_analysis.json`、各种子的最终评估及原批次结果；当前不能声称课程带来导航成功或网络收敛。

课程组 100,000-transition Replay 中，满足单机目标捕获条件的相关动作前状态数为 60/225/181。按回放插入次序审计，属于短程阶段的分别为 43/225/180，属于完整任务阶段的为 17/0/1；后者也不是独立的回合成功次数。原始审计见 `results/masac_v3_goal_curriculum_20261102/goal_coverage_by_stage.json`。这支持继续追踪完整任务的到达经验，但不足以证明任务学会或确定需要多少额外步数。

## 唯一训练干预与预算

从两条 Standard MASAC 历史各自保存的 100,000 步最终检查点和对齐 Replay 原样续训至 **300,000 总环境步/种子**，训练种子仍为 411、422、433。两条历史各增加 200,000 步/种子，合计新增 1,200,000 环境步；每个种子目标 299,000 次 SAC 更新，其中本轮新增 200,000 次。100,000→300,000 和 200,000 新步是预先定义的开发预算假设，用户希望增加轮次，现有证据不证明这一预算必然足够或有效。日志同时报告环境步、更新数和已结束回合数，三者不是同一单位。

运行顺序固定为课程历史的 411/422/433，再是原始历史的 411/422/433，单任务单 CPU 线程；每个种子独立继承自己的模型、优化器、状态和随机流。奖励、动力学、碰撞、阶段判定、actor/critic 网络和容量、优化器、SAC 更新比例、温度、折扣、截断 bootstrap 语义、Replay 容量、地图生成规则及验证频率沿用各自父批次，不重置模型、Replay、进行中的回合或随机流，也不重新暖身。课程父批次三个最终检查点均处于 `full`，后续任务按其课程协议继续处于 `full`。每次成功或碰撞仍按原语义终止，350 步截断仍按原设定处理。

Replay 是容量 100,000 的 FIFO 环形缓冲，父检查点已满且写入位置为 0。课程历史起始回放含约 30,000 条短程数据，这些数据将在新增约 30,000 步时逐步被覆盖；新增 100,000 步后父回放全部被新完整任务数据替换。训练经验分布会自然变化，因此不能称回放数据分布保持不变；即使短程样本消失，先前课程可能仍通过网络和优化器状态影响结果。

## 运行前完整性与恢复

两父目录均须 `completion.json` 表示三种子完整、无 `error.json`，状态与 `results/masac_v3_active_run.json` 已核对且无运行中的竞争任务。对每个分支及种子检查父协议、`audit.json`、最终步 100,000 的 checkpoint、Replay、评估记录、seed、更新数、容量、写入指针和环境阶段；课程检查点须明确 `exact_resume` 和 `full`，且保留其进行中回合的开始步、回报、环境和逐机统计。原组已保存回合状态和回报；如果父批次没有完整逐机诊断历史，将跨续训点的那一回合显式标为部分统计，不虚构回合初始数据。

续训器核验三份共同算法源码及其父快照哈希；课程组还核验课程环境、训练器、评估及恢复辅助函数、课程协议的当前源码和父快照哈希，并保存各父 checkpoint、Replay 的 SHA-256 与读取路径。已有 Replay 审计哈希可用于核验；首次计算的 checkpoint 哈希只作为本轮来源指纹，不证明先前已有独立完整性记录。恢复 Actor、两个 Critic、目标网络、三个优化器、alpha、Replay 全数组/大小/环形指针、环境、回合回报、Python、NumPy、Torch、Replay 采样与探索 RNG。若任一检查失败，写入错误标记并保留已有产物，不启动该批或静默跳过种子。

在正式运行前，测试对齐父状态恢复后下一随机动作、环境转移、Replay 写入/采样、一次 SAC 更新与权重/RNG，与不中断路径逐项一致；覆盖满容量 Replay 的环形写入跨边界、进行中回合和课程阶段恢复。进行独立短烟测，明确烟测不作为科学结果且不覆盖正式活动指针。参考父续训脚本时须修正其只校验三个共同源码、将课程环境恢复为普通环境并标记旧协议的局限。

## 输出、监控和统计

使用新结果目录、独立日志和进程锁，旧结果、源码快照与未提交工作全部保留。每 100 步输出训练历史、种子、实际环境步、更新数、回合数、损失、温度、速度、ETA 和最近验证步数。每 2,000 步在与父实验相同的六张原完整开发地图进行确定性 Actor 评估，保存逐图结果和轨迹；每 10,000 步保存模型检查点。每 50,000 步（150k、200k、250k、300k）保存完整、同一步的 checkpoint 与 Replay，并用独占目录、哈希及完成标记表明可恢复；其余模型检查点不可声称能精确恢复。异常写 `error.json`；全部六个训练历史/种子成功完成并保存最终结果后才写 `completion.json`。不覆盖任何历史文件。

每训练历史及每个训练种子的最终 300,000 步结果完整报告；同种子比较 100,000 与 300,000 步可观察各自续训的开发变化；两种训练历史之间的对比只使用相同预算、相同开发地图和同一随机种子标签。相同标签不保证经历相同训练地图，因为两条历史的回合长度与地图轮换不同。报告所有成功与失败、碰撞标记及重叠、超时、剩余距离和样本覆盖；失败路径长度不当作成功效率。统计独立单位是训练种子，不是同一模型的六张图；不挑中途最佳检查点。

六张地图反复用于开发，不是最终独立确认集；若后续为诊断而选用新地图，应先冻结并标记为新开发集，仍需另留未查看的确认集。不同预算的课程与无课程结果不能用于宣称课程优势；未建立 Standard MASAC 导航能力前不运行四个机制对照，不宣称安全、创新或收敛。

固定机器可读配置：`configs/masac_v3/paired_300k_protocol.json`；本设计、配置、续训器和所有执行源码须随新结果目录快照并记录 SHA-256。
